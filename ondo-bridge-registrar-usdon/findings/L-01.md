# L-01: USDon redemption truncates dust during `18 -> 6` decimal conversion

- Source: [Cantina public report](https://cantina.xyz/portfolio/91210482-130b-478a-848c-773029679a90)

## Issue

`USDonConverter.redeem()` divides by a fixed `1e12` rate. If the input is not cleanly divisible, the remainder dust is silently truncated.

## Invariant

If a redemption path converts across decimal domains, the treatment of remainder dust should be explicit.
