# L-01: USDon redemption truncates dust during `18 -> 6` decimal conversion

## Summary

`USDonConverter.redeem()` converts `USDon` to `USDC` using integer division against a `1e12` rate.

When the input amount is not cleanly divisible by that rate, the remainder is truncated.

## Invariant

If a redemption path converts between decimal domains, the conversion behavior should be explicit rather than silently dropping remainder dust.

## Impact

Small dust amounts are lost on redemption whenever the input contains non-zero digits below the `USDC` precision boundary.

## Fix direction

Either:

- require exact divisibility, or
- explicitly handle and document dust refunds / dust retention
