# M-01: Missing `BURNER_ROLE` breaks OFT outbound bridging

## Summary

`BridgeRegistrar.register()` grants the new OFT `MINTER_ROLE`, but does not grant `BURNER_ROLE`.

Because the OFT outbound send path burns local tokens inside `_debit(...)`, every cross-chain send will revert until the role is granted manually.

## Why this is a real issue

The token is registered as if the OFT path is ready, but the token-side burn permission is still incomplete.

That breaks the main outbound bridge flow:

1. user calls `send(...)`
2. OFT calculates debit amount
3. OFT calls `innerToken.burn(_from, amountSentLD)`
4. token checks `onlyRole(BURNER_ROLE)`
5. call reverts because OFT does not have that role

## Invariant

If a token is registered for OFT bridge use, the OFT must have all token-side roles required by the live debit / credit path.

## Root cause

Role provisioning in `register()` is incomplete:

- `MINTER_ROLE` is granted
- `BURNER_ROLE` is omitted

## Impact

Outbound cross-chain transfers fail completely for the registered token until manual intervention happens.

## Fix direction

Either:

- grant `BURNER_ROLE` during registration, or
- change the debit-side token integration so it uses the intended burn primitive for the token design
