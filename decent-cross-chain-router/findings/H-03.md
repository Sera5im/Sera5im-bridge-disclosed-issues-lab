# H-03: Failed destination execution refunds bridged WETH to the wrong address

## Summary

When the destination execution path fails, the bridge executor refunds the bridged WETH to `_from`.

Under normal Decent flow construction, `_from` is not the real user-controlled refund address. It is an internal bridge-side address embedded into the payload, so failed executions can send the entire bridged amount to the wrong destination-side recipient.

## Invariant

If a destination-side execution fails after bridging, the refund path must return value to the intended user refund recipient, not to an internal bridge or adapter address carried in the payload.

## Root cause

`DecentEthRouter.onOFTReceived(...)` forwards `_from` into:

- `DecentBridgeExecutor.execute(_from, _to, deliverEth, _amount, callPayload)`

Then the executor failure path refunds to `from`.

That creates a semantic mismatch:

1. `_from` is treated as a refund recipient
2. but the payload encoding does not guarantee `_from` is the user

## Impact

If the destination execution reverts, the bridged amount can be refunded to the wrong address.

That can cause full user fund loss for the failed cross-chain call because the user does not control the refund destination actually used by the executor.

## Fix direction

Pass and use an explicit destination-side refund address in the payload and make the executor refund to that address instead of `_from`.
