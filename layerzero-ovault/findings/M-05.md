# M-05: Inconsistent slippage checks can create stuck-funds behavior

## Summary

A local path can accept parameters that later fail deeper in the endpoint-side debit / normalization logic.

When the early path and the later path enforce different slippage assumptions, the action can progress into a state that cannot actually complete.

## Invariant

All slippage-sensitive stages of the same send flow should agree on the same effective amount semantics before the system commits to execution.

## Root cause

The local action path and the downstream endpoint debit path use different slippage checks, so a transaction can pass locally but still fail after dust-removal or normalization.

## Impact

Users can encounter stuck-funds or failed-recovery behavior caused by inconsistent acceptance criteria across the same logical flow.

## Fix direction

Align slippage validation between local execution and downstream debit / normalization so both layers reason about the same effective amount.
