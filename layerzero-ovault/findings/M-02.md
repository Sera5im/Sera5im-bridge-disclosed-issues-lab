# M-02: Slippage constraints can leave failed flows locked without a practical recovery path

## Summary

When a failed flow later retries under a slippage-constrained path, the retry can keep reverting if market conditions no longer satisfy the original minimum output expectations.

If no alternative recovery route exists, the failed state remains active and the funds stay locked behind retry conditions that cannot be met.

## Invariant

If a failed action enters recovery mode, there must be a realistic escape path that does not depend forever on the exact same slippage conditions that already caused the failure.

## Root cause

Recovery logic reuses slippage-sensitive execution assumptions without guaranteeing a fallback path that can safely unwind or return value when those assumptions stop being satisfiable.

## Impact

Funds can remain temporarily or permanently stuck in recovery state.

## Fix direction

Add a deterministic fallback path for failed slippage-bound flows, such as direct refund or alternative unwind logic that does not depend on the same execution conditions.
