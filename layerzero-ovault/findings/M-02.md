# M-02: Slippage constraints can leave failed flows locked without a practical recovery path

- Source: [Cantina public report](https://cantina.xyz/portfolio/e4d93441-0fe3-4b64-bf98-fa31ecef4fb5)

## Issue

If recovery reuses the same slippage-sensitive assumptions that already failed, retries can keep reverting forever. Without a real fallback path, the failed state can stay locked.

## Invariant

Recovery mode must have an escape path that does not depend forever on the same slippage conditions that already broke execution.
