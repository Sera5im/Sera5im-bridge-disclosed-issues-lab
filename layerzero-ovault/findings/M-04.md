# M-04: Native value can become trapped and must be paid again on retry

## Summary

The compose / retry flow can leave previously supplied native value stranded inside the failed-message path while the retry still requires fresh `msg.value`.

That means the user can lose access to the original native payment and still be forced to pay again to continue recovery.

## Invariant

If native value is supplied to a failed cross-chain action, retry or recovery logic must either reuse that value or return it before requiring additional payment.

## Root cause

The retry path does not correctly account for native value already attached to the failed execution state.

## Impact

Native value can be trapped, and retries may require duplicate payment.

## Fix direction

Carry forward previously supplied native value during recovery, or explicitly refund it before demanding a new payment attempt.
