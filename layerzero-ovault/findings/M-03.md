# M-03: Retry path fails when `dstEid == HUB_EID`

## Summary

The normal send path handles the local hub route correctly, but the retry-style path can still fall into generic peer validation even when the destination is the hub itself.

That creates path divergence between:

1. the happy path
2. the retry / recovery path

## Invariant

If the system treats `dstEid == HUB_EID` as a special local route during normal execution, recovery and retry paths must preserve the same routing semantics.

## Root cause

The retry-side logic does not consistently preserve the hub-special-case handling used by the normal send path.

## Impact

Transfers targeting the hub can fail in retry / recovery mode even though the equivalent normal execution path is valid.

## Fix direction

Unify hub-routing behavior across both normal and recovery paths so retry logic cannot accidentally fall back to generic peer checks.
